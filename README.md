# 通用记账Book

一个**纯本地**的微信小程序记账本：把支付宝 / 微信的账单导入进来，自动去重、自动分类、出报表。数据只存在手机本地的小程序 Storage 里，不上传、不需要服务器。

> 起因很简单：市面上的记账 App 要么得手动一笔笔记，要么云端同步、把人家的消费明细存到别人的服务器上。这个项目只做一件事——**把官方导出的账单变成能看的账，数据始终留在自己手机上。**

## 它有什么

- **三条导入入口**：账单文件（微信 `.xlsx` / 支付宝 `.csv`，整年一次导完）、截图识别（滚一张长图，OCR 成流水）、复制粘贴（兜底，什么环境都能用）
- **判重只认交易单号**，同一天同金额同商户绝不合并（真实账单里这种「疑似重复」大量存在，按日期+金额去重会把真流水吃掉）
- **分类对齐「微信记账本」官方口径**：支出 19 / 入账 9 / 不计收支 3，另有内置关键词词库 + 手动改一次就记住的商户规则
- **报表**：分类构成环形图、每日支出柱（1×/2×/3× 放大）、近 6 个月对比、每日花销日历热力图、年度汇总（分类排行可展开、点开进分类明细页按月看、逐笔点开看详情）、商户排行（支出榜 + 入账榜）、月度 / 分类预算、分类环比
- **只保留最近一年**：时间跨度超过 12 个月时，最老的流水自动清掉，避免本地 Storage 单 key 1MB 的上限被撑爆
- **一键备份 / 恢复**：全量导出 JSON、按现有判重规则合并恢复

## 技术要点

| 位置 | 说明 |
|---|---|
| `utils/store.js` | 本地存储 + 判重（单号型 `b` / 截图型 `h` / 手记 `m`）+ 一年截断 |
| `utils/parser.js` | CSV / TSV / 从 Excel 复制出来的制表符文本 → 流水 |
| `utils/ocrbill.js` | OCR 文字块（带坐标）→ 按纵向聚行 → 抠金额/商户/日期 → 流水 |
| `utils/stats.js` | 月度汇总、趋势、日历、洞察、年度汇总 |
| `utils/category-rules.js` | 纯数据的关键词词表，补分类只改这个文件 |
| `cloudfunctions/parseBill` | 自带一个零依赖的 zip + XML 读取器，直接解微信 xlsx；支付宝 CSV 自动识别 GBK |
| `cloudfunctions/ocrText` | 微信云调用 OCR（额度不够时自动退到百度 OCR） |

云函数只做「文件 → 结构化数据」和「图片 → 文字」，**流水一条都不上云**，识别完立刻删掉云存储里的图。云环境不续费也不影响本地账本。

## 跑起来

1. 微信开发者工具 → 导入项目 → 选这个目录
2. AppID 填你自己的（仓库里是 `touristappid` 游客号，只能模拟器跑）
3. 纯本地记账不需要云开发；要用「截图识别」和「xlsx 导入」才需要开通云开发，并部署 `cloudfunctions/` 下两个云函数
4. 百度 OCR 的 Key **不要写进代码**：云开发控制台 → 云函数 `ocrText` → 配置 → 环境变量，加 `BAIDU_API_KEY` / `BAIDU_SECRET_KEY`

详细操作手册（怎么导出支付宝/微信账单、为什么这么设计、各种坑）见 [`使用说明.md`](./使用说明.md)。

## 隐私

- 仓库里**没有任何真实账单数据**，也没有 API Key、AppID
- 运行时数据全在手机本地 Storage，卸载小程序 / 清缓存即消失
- 云端只经过图片文字识别这一跳，图片用完即删

## 已知限制

读不了支付通知（系统权限）、读不了 PDF 账单、无法直接拉取支付宝/银行流水、截图 OCR 会认错金额（有预览可核对）、不会多端同步。
