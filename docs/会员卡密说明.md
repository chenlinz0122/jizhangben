# 会员卡密说明

小程序里**不做任何支付**，只做「输入卡密 → 核销」。卡密在小程序外卖（闲鱼、微信、群里都行），
这样既不碰微信支付的资质门槛，也不会因为「小程序内展示收款码」被审核驳回或封号。

## 一、免费版 / 会员版的界线

| 功能 | 免费版 | 会员版 |
| --- | --- | --- |
| 首页、手动记一笔、流水、总览 | ✅ | ✅ |
| 报表：本月总额 / 支出构成 | ✅ | ✅ |
| 报表：每日趋势、近 6 个月对比、年度汇总、商户排行、每日日历 | ❌ | ✅ |
| 月度预算 / 分类预算 | ❌ | ✅ |
| AI 补分类 | ❌ | ✅ |
| 截图识别（相册/拍照认账单） | ❌ | ✅ |
| 账单文件导入（微信 .xlsx / 支付宝 .csv） | ❌ | ✅ |
| 粘贴文本快速解析 | ✅ | ✅ |

> 报表不做「全锁」：本月总额和支出构成免费，让人先看见自己的钱在哪；想看趋势、对比、排行、预算才要会员。免费版在构成卡下面挂一张「想解锁更多」的引导卡，点进去输卡密。
> 粘贴解析留着免费，是为了让新用户能「五分钟看到效果」；其余项都有真实成本（OCR 额度、云函数、算力）或高感知价值。

## 二、部署（缺一步就断）

1. **建两个集合**（云开发控制台 → 数据库）
   - `codes`：卡密台账
   - `members`：会员台账
   两个都设「**仅管理端可读写**」——小程序端不可读写，只有云函数能访问。

2. **上传云函数**
   开发者工具里右键 `cloudfunctions/vip` → 「上传并部署：云端安装依赖」。
   > 这个函数还兼着「登录身份」：`status` 会把当前微信的 openid 一起返回，登录页靠它认人。所以这个函数没部署，登录也拿不到 openid（账本能用，会员兑不了）。

3. **生成卡密**（本地，无需联网）
   ```bash
   node tools/gen-codes.js 100 365     # 100 张 / 年卡
   node tools/gen-codes.js 50 30       # 50 张 / 月卡
   ```
   产物在 `tools/out/codes-<批次>.json`，一行一个对象。

4. **导入卡密**
   控制台 → 数据库 → `codes` → 导入 → 选上面的文件 → 字段自动匹配 → 开始导入。
   `usedBy` 必须是空字符串，云函数靠它做「条件更新」抢码，缺了字段就兑不了。

5. **自测**
   - 自己的微信先兑一张 → 报表锁屏应立刻消失、到期日正确
   - 换另一个微信兑同一张 → 应提示「这张卡密已经被用过了」
   - 同一张再提交一次 → 提示「这张已经兑过了」，到期日**不重复加天**

## 三、数据结构

`codes`
```json
{ "code": "ABCDEFGHJKLMNPQR", "codeText": "ABCD-EFGH-JKLM-NPQR", "days": 365,
  "usedBy": "", "usedAt": 0, "batch": "B20261120", "createdAt": 1763600000000 }
```

`members`
```json
{ "openid": "oXXXX...", "expireAt": 1800000000000, "code": "ABCDEFGHJKLMNPQR", "updatedAt": 1763600000000 }
```

## 四、口径与限制

- **一码一人**：抢码用「只有 usedBy 为空的那次更新才能成功」，并发/断网重试都不会兑两次。
- **续期叠加**：未过期时在原到期日上累加（提前续费不吞天数），已过期则从当天重新算。
- **本地缓存**：会员状态缓存在本地，断网按缓存宽限。记账工具盗版成本极低，不建议上强校验——那只会折磨正常用户。
- **不退款**：卡密核销后无法回收。真要做退款，只能在 `codes` 里人工置回 `usedBy:''` 并把 `members.expireAt` 改回去。
- **卡密可被转发**：首次兑换绑定 openid，转发给别人就作废了；但截图外泄仍可能被抢兑，所以发码尽量一对一。
- **定价参考**：年卡 39～59 元、月卡 8.9～12 元。你不是在卖「记账」，是在卖「截图识别 + 报表」，价格别对标免费竞品。
