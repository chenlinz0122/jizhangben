# 会员卡密说明

小程序里**不做任何支付**，只做「输入卡密 → 核销」。卡密在小程序外卖（闲鱼、微信、群里都行），
这样既不碰微信支付的资质门槛，也不会因为「小程序内展示收款码」被审核驳回或封号。

## 一、免费版 / 会员版的界线

| 功能 | 免费版 | 会员版 |
| --- | --- | --- |
| 首页、手动记一笔、流水、总览 | ✅ | ✅ |
| 报表：本月总额 / 支出构成 | ✅ | ✅ |
| 报表：每日趋势、近 6 个月对比、年度汇总、商户排行、每日日历 | ❌ | ✅ |
| 月度预算 / 分类预算 | ❌ | ✅ |
| AI 补分类 | ❌ | ✅ |
| 截图识别（相册/拍照认账单） | ❌ | ✅ |
| 账单文件导入（微信 .xlsx / 支付宝 .csv） | ❌ | ✅ |
| 粘贴文本快速解析 | ✅ | ✅ |

> 报表不做「全锁」：本月总额和支出构成免费，让人先看见自己的钱在哪；想看趋势、对比、排行、预算才要会员。免费版在构成卡下面挂一张「想解锁更多」的引导卡，点进去输卡密。
> 粘贴解析留着免费，是为了让新用户能「五分钟看到效果」；其余项都有真实成本（OCR 额度、云函数、算力）或高感知价值。

## 二、部署（缺一步就断）

1. **建两个集合**（云开发控制台 → 数据库）
   - `codes`：卡密台账
   - `members`：会员台账
   两个都设「**仅管理端可读写**」——小程序端不可读写，只有云函数能访问。

2. **上传云函数**
   开发者工具里右键 `cloudfunctions/vip` → 「上传并部署：云端安装依赖」。
   > 这个函数还兼着「登录身份」：`status` 会把当前微信的 openid 一起返回，登录页靠它认人。所以这个函数没部署，登录也拿不到 openid（账本能用，会员兑不了）。

3. **生成卡密**（本地，无需联网）
   ```bash
   node tools/gen-codes.js 100 365     # 100 张 / 年卡
   node tools/gen-codes.js 50 30       # 50 张 / 月卡
   ```
   产物在 `tools/out/codes-<批次>.json`，一行一个对象。

4. **导入卡密**
   控制台 → 数据库 → `codes` → 导入 → 选上面的文件 → 字段自动匹配 → 开始导入。
   `usedBy` 必须是空字符串，云函数靠它做「条件更新」抢码，缺了字段就兑不了。

5. **自测**
   - 自己的微信先兑一张 → 报表锁屏应立刻消失、到期日正确
   - 换另一个微信兑同一张 → 应提示「这张卡密已经被用过了」
   - 同一张再提交一次 → 提示「这张已经兑过了」，到期日**不重复加天**

## 三、数据结构

`codes`
```json
{ "code": "ABCDEFGHJKLMNPQR", "codeText": "ABCD-EFGH-JKLM-NPQR", "days": 365,
  "usedBy": "", "usedAt": 0, "batch": "B20261120", "createdAt": 1763600000000 }
```

`members`
```json
{ "openid": "oXXXX...", "expireAt": 1800000000000, "code": "ABCDEFGHJKLMNPQR", "updatedAt": 1763600000000 }
```

## 四、口径与限制

- **一码一人**：抢码用「只有 usedBy 为空的那次更新才能成功」，并发/断网重试都不会兑两次。
- **续期叠加**：未过期时在原到期日上累加（提前续费不吞天数），已过期则从当天重新算。
- **本地缓存**：会员状态缓存在本地，断网按缓存宽限。记账工具盗版成本极低，不建议上强校验——那只会折磨正常用户。
- **不退款**：卡密核销后无法回收。真要做退款，只能在 `codes` 里人工置回 `usedBy:''` 并把 `members.expireAt` 改回去。
- **卡密可被转发**：首次兑换绑定 openid，转发给别人就作废了；但截图外泄仍可能被抢兑，所以发码尽量一对一。
- **定价参考**：已定三档 —— 月卡 30 天 ¥6.9（约 0.23/天）、季卡 90 天 ¥15.9（约 0.18/天）、年卡 365 天 ¥39（约 0.11/天）。卡密不分档别，天数写在 `codes.days` 里。

## 五、自动建库（不用去控制台手点）

`cloudfunctions/vip` 里内置了一份 `codes.json`（70 张：30 天 20 张、90 天 10 张、365 天 40 张）。第一次在崭新云环境里被调用时，它会自己：

1. 建 `codes`、`members`、`feedbacks` 三个集合（已存在就跳过）；
2. `codes` 里一条都没有时，把内置的 70 张灌进去（已存在同号就跳过，反复跑不会重复）；
3. 然后再执行这次请求本身。

触发点有三处，任一处跑到就生效：`app.js` 冷启动带 `cloud_inited_v1` 标记调一次 `action:'initdb'`；`pages/login/login.js` 的 `onLoad` 顺手续一次 `vip.refresh()`；任何 `vip.status` / `vip.redeem` 撞到「集合不存在」都会自动补建后重试。

所以**部署完三个云函数就能直接兑码**，不需要再去控制台建集合、导 JSON。

自己往库里加新批次时，仍然可以用控制台「导入」`tools/out/codes-import-*.json`（一行一个对象）。注意集合权限保持默认的「仅创建者可读写」也安全：小程序端从来不直接读写这两个表，全部走云函数。


## 六、邀请好友（已上线代码，双方各 +7 天）

- 会员页「邀请好友」卡片 → 转发给朋友，链接里带 `?invite=<码>`；对方首次打开自动 +7 天，你同时 +7 天。
- 邀请人最多拿 5 次（`INVITE_MAX`），被邀请人一个微信号一辈子只算一次；不能邀请自己。
- 数据表：`invites{openid, code, codeText, createdAt}`、`invite_logs{inviter, invitee, code, days, rewarded, at}`。
- 口径改在 `utils/config.js` 的 `INVITE` 和云函数 `INVITE_DAYS / INVITE_MAX` 两处（页面文案读 config，云函数读常量）。

## 七、推广得会员（发帖 / 评论换会员，参考一木「种草得会员」）

- 页面：`pages/promo/promo`，入口在会员页「推广得会员」卡片。
- 门槛：浏览量 ≥1000 → 月卡（30 天）；≥5000 → 季卡（90 天）；≥12000 → 年卡（365 天）。评论区推荐、50 赞 → 月卡。
- 流程：用户填平台 + 浏览量 + 帖子链接 + 联系方式 + 数据截图 → 走 `feedback` 云函数（type=other，正文前缀「【推广兑换】」）→ 你在 `feedbacks` 集合里看到 → 核对后从取码工具取一张对应天数的码发给他。
- 为什么不做成自动发放：浏览量真伪必须人工看一眼（一木也是人工审）。等量大了再做后台页面。
- 口径在 `utils/config.js` 的 `PROMO`：门槛、天数、文案一处改。
